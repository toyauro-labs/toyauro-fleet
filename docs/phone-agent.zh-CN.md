# 手机 Agent 与控制层

## 定位

手机上的 Agent 是能观察环境、执行任务和验证结果的独立工位。它可直接组合 Android 系统能力、Shell、已有工具和自编脚本；需要另一台设备协助时再通过现有连接协作。

既有私有环境使用 Android、Termux 和 Root，并以 `phone-agent` 为操作入口。相关实现和依赖当时并未包含在本仓库中；下文是设计与实测快照，不是当前仓库的安装指南。

```text
手机 Agent（例如 Pi）
    ├─ Shell / Android 命令
    └─ phone 工具或 phone-agent CLI
                ↓
        常驻 Root UI 桥接服务
                ↓
     Android UiAutomation / 原生命令
                ↓
             真实手机界面
```

Pi 的 `phone` 扩展调用已有 CLI；桥接服务复用本机 Unix socket 和常驻 UiAutomation 连接。按控件读取、选择、输入与系统命令互补；不能读取控件时可以观察实际截图，再决定是否有足够证据操作。截图返回成功、界面真实可见、目标动作完成是不同的验证点。

## 真机评测：2026-10-29

同一台 Android 16 测试手机的设置页面，表中是各组三次本机测量的中位数，不包含模型响应或远程 SSH 时间。调用的检查和图像格式不同，不能作为严格同条件排名。

| 路径 | 操作 | 三次样本（ms） | 中位数（ms） | 范围 |
| --- | --- | --- | --- | --- |
| `phone-agent` 完整 CLI | 读取 UI 树 | 2345、2700、2706 | 2700 | 返回设置窗口，包含 CLI 和相关检查 |
| `phone-agent` 亮屏快路径 | 连续读树 | 392、419、406 | 406 | 另一次记录；中文输入后读取一致 |
| Android `uiautomator dump` | 读取 UI 树 | 2147、2150、2156 | 2150 | 退出码成功；这三份 XML 未逐一验内容 |
| UIAutomator2 常驻服务 | 读取 UI 树 | 72、22、31 | 31 | 修正活动窗口参数后，独立复测中文输入与回读 |
| 现有 Root UI 服务直连 | 读取 UI 树 | 20、13、12 | 13 | 底层接口实验，不是完整 CLI 路径 |
| `phone-agent` 完整 CLI | 截图 | 3199、3353、3268 | 3268 | 返回成功；另一项熄屏启动截图经人工确认有内容 |
| Android `screencap` | 截图 | 334、389、357 | 357 | 命令成功，三张未逐一人工验图 |
| UIAutomator2 常驻服务 | 截图 | 219、107、131 | 131 | 返回 JPEG，图像格式和检查与 CLI 不同 |

记录中的完整 CLI 中位数与另一次亮屏快路径之比约 6.7；由于不是严格同条件前后实验，不能把它解释为任何任务都快 6.7 倍。13 ms 直连也不包含 CLI、状态检查、唤醒、模型决策或结果验证。

从物理面板关闭状态开始的独立测试中，打开设置、读取窗口和截图各需约 4.86、4.64、5.22 秒，分别包含唤醒与恢复；另一轮记录的熄屏启动设置约 3.8 秒。可能的优化是让同一次任务复用受控 UI 会话，减少重复唤醒和检查；须测完整任务成功率与耗时，不能只报内部函数延迟。

其他候选：Mobilerun Portal 在设置页读树有样例，微信测试页未获得有效树；`parallel-root` 的虚拟显示能打开设置、输入和截图，但重复截图、生命周期、应用迁移与并发仍需验收。UIAutomator2 是可参考的备选，不能由设置页结果推断所有 App 均可操作。

## 执行与语音：实际边界

- 手机 Pi 曾通过已激活的 `phone` 工具调用本机能力；文字请求到手机 Pi 执行再回写聊天有真实样例。
- 语音与数字音频桥有局部验证和历史双向通话样例；实时转写、程序结果、数字音频活动和对端确实听到，是不同证据。当前版本的真实呼入、执行、语音回报完整闭环仍需验收。
- 微信部分界面曾返回空树或黑图；单次 `ok: true` 不代表有可用节点，一张截图文件也不证明图像内容有效。应确认实际前台、设备/显示状态与画面内容，再诊断原因。
- Root UI 入口具备高权限；工位名称不是权限隔离。不要把外部页面或消息文本当作工具执行授权。

## 后续实验

从真实任务选择稳定的 UI 操作、中文输入和一次需看截图的流程；记录总耗时、成功率、恢复次数及操作后的可观察结果。比较常驻连接、亮屏会话复用和原生命令。只有反复出现且验证稳定的流程才考虑封装成专用 CLI；优先保留 Agent 自主观察与选择路径的能力。
